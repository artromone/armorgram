# SPEC — armorgram (минимальный SMS-клиент с bridge, финальная)

> Источник истины. Отменяет approval/командный флоу из `BRIDGE_PLAN.md`
> (тот оставлен как история). Цель: лёгкое приложение для кнопочного-телефона-
> заменителя в армии — видеть входящие TG-сообщения (пришедшие SMS-кой с
> gateway-номера как виртуальные чаты) и быстро отвечать. Ничего лишнего.

## Что уже работает (bridge ~70%)

`Wire.kt` (кодек), перехват приёма `ReceiveSms.kt:72`, перехват отправки
`MessageRepositoryImpl.kt:298`, виртуальные чаты в Realm, дедуп в памяти,
сборка chunked-фреймов. Настройки bridge есть, но запускаются только через adb.

## КРИТИЧНО (без этого пользоваться нельзя)

### 1. Уведомления на bridge-сообщения
Сейчас при перехвате `ReceiveSms` делает `return@mapNotNull null` (стр. 73),
поэтому пропускается `notificationManager.update(threadId)` (стр. 102) — телефон
не звякает, значок не появляется. **Чинить обязательно.**

План: `BridgeRepository.routeIncoming` вместо `Boolean` возвращает список
`threadId` виртуальных чатов, в которые легло новое **входящее** (null/пусто =
«не моё, провалиться дальше»; пусто-но-consumed для ack/sys — без уведомления).
В `ReceiveSms`: если consumed → для каждого threadId вызвать
`notificationManager.update(it)` и `updateBadge`, затем `return null`.

### 2. Bridge-настройки в обычном Settings
Сейчас только `adb am start ...BridgeSettingsActivity`. Добавить пункт «Bridge»
в основной экран настроек (открывает этот же Activity). Нужны минимум:
gateway-номер, вкл/выкл, сброс out-seq. **Убрать** командный UI (`/approve`,
`/block`, `/wl`) — заявок больше нет. Оставить одно поле «resend LO-HI» как
ручной триггер восстановления (сервер поддерживает `/resend`).

## Чистка UI (прятать, код модулей НЕ удаляем)

Спрятать из меню/настроек/навигации, чтобы не путало:
- QKSMS Plus / биллинг / донаты / upsell.
- Changelog-попап.
- Отложенные сообщения (scheduled).
- Backup / restore.
- Менеджер блокировок (blocking) — спрятать пункт.
- Галерея / MMS-вложения — кнопку вложения в compose спрятать (только текст).
- Виджет, QK Reply — опционально спрятать.

Оставить:
- Список чатов, ввод и отправка текста, уведомления.
- Настройки: тема, ночной режим, размер текста, подпись (signature), отчёты о
  доставке (delivery), настройки уведомлений (звук/вибра).

## Не-фрейм SMS с gateway-номера

Решение (низкозатратное): **не прятать** обычный SMS-тред gateway-номера. Если
с него придёт не-фрейм (напр. «баланс» от оператора) — он просто покажется как
обычная SMS от этого номера. Никакого `_sys`-дублирования и фильтра списка не
делаем (предсказуемо и меньше кода).

## Отложить (MVP работает без этого)

- Персистентный дедуп (`bridge_in_seq`) — сейчас в памяти, ок.
- TTL для недособранных chunked-фреймов.
- Таблица `AliasContact` (alias→имя) — имя из `?NEW` сейчас и так пишется в
  `Conversation.name`.
- HMAC-подпись фреймов.
- **Индикатор доставки ответа** (PendingIntent/SmsSentReceiver для виртуальных
  отправок) — *рекомендуется следующим шагом*: даст знать, что твой ответ реально
  ушёл (важно при возможных блокировках оператора). Не блокер для первой сборки.
